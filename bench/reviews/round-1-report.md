# Astra report-selector review

REQUEST_CHANGES. Scope: report.py, its tests, run.py timing suppression, README, and sol-measurement-handoff.md. No live service, provisioning or measurement executed. Parent owns full-suite execution. Mutable review references were treated as parent attestations, not an authentication boundary.

Offline repro: `python3 -B /tmp/astra-report-r1/probe.py`. It creates synthetic receipts through the existing offline Scenario fixture. All three probes build correctly hashed manifest attempts; none relies on a stale hash silently being accepted.

1. P1, bench/report.py:200-202. A raw log reference can resolve outside the run tree. Only existence is checked, while tree_digest covers only files under the run directory. The reproduction moves a repeat-read stdout to an absolute external path, records that path in steps.jsonl, takes the manifest hashes, then changes the external log. The digest remains unchanged, evidence_problems is empty, and all four metrics are reported. This breaks the stated hash verification of referenced logs and makes the report dependent on unpinned evidence. Require resolved log paths to remain inside the run directory, including symlink resolution, or explicitly hash every external referenced file. Test absolute paths, ../ paths, and normal in-tree logs.

2. P2, bench/report.py:475 coverage_complete expression. Completeness excludes only coverage strings starting with `missing`. A selected attempt with a nonexistent directory produces `evidence missing: ...`, which is counted complete. A manifest with all 26 tools selected against nonexistent directories therefore has coverage_complete=True and would pass --require-complete. Determine completeness from loaded evidence and explicit declared blocked/untested states, not a string-prefix mismatch. Preserve invalid-but-present diagnostic attempts as appropriate; missing selected evidence must not satisfy the completeness flag.

3. P2, bench/report.py:193-194 and :401-405. Step validation does not check inner_ns at all and does not require nonnegative outer_ns. The repeat selector accepts negative inner durations, recomputes matching summaries, and reports p50/p95=-0.9 ms with all three samples marked available. This is not only arbitrary JSON corruption: Docker inner timing uses EPOCHREALTIME, so a backward wall-clock adjustment can create negative durations. Validate duration types/ranges before emitting numbers. inner_ns may be null, otherwise require a nonnegative integer; outer_ns likewise must be nonnegative. Reject affected evidence or omit the invalid inner statistic with an explicit reason, rather than reporting it as measured latency.

No further verified findings from this bounded review. Serial interval comparisons, metadata/protocol equality, metric outcome gates, warmup/sample counts, raw read semantic checks, distribution recomputation, and invalid/provision-blocked timing suppression are present.
