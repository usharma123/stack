Verdict

The core local bundle and session vision is demonstrated for Postgres and Redis. 0.1.3 is a credible base for a controlled pilot. The broader agent-safe product is not complete.

Demonstrated

Reusable bundles with files, per-checkout ports and data, live instance verification, endpoint poisoning and refusal, structured errors, MCP, commit and digest pinning, confirmed shutdown.

Partial

Tool versions are ranges or latest. Custom services are liveness-only. Leases reclaim lazily. macOS has a lifecycle smoke test, not the full suite.

Not evaluated

Real multi-agent work, concurrency stress, remote backends, hosted or private OCI auth, x64 hardware, repeated timing studies.

No completion percentage is given: the vision has no agreed weighting, and several areas were not exercised at all. Status labels below are qualitative and each links to evidence.

Corrections and observed issues

First-attempt summaries are published at stack-0.1.3-attempt1 and stack-0.1.3-native-attempt1. Final results above come from the corrected runs. Raw logs are preserved locally and excluded from Git.

Outdated MCP test assertion

Test maintenance

The existing E2E asserted 7 MCP tools; 0.1.3 ships 9 (adding stack_doctor and stack_gc). Suite 4 failed in the first attempt. The assertion now checks the exact nine tool names, and all six suites passed on rerun.

attempt 1 summary · attempt 1 scenarios

Invalid-package benchmark

Benchmark correction

In the first attempt, bad_pkg and bad_version ran without a compile and stopped at lock_outdated, never reaching install. The harness now compiles first and asserts install_failed. The 3 ms first-attempt timings are invalid.

attempt 1 · final

macOS socket path limit

Provider constraint

The first native run put isolated state under a deep artifacts path. Pitchfork's socket path was 118 bytes against the macOS 104-byte cap. Stack returned structured start_failed with retry_safe: true. A short /tmp state path passed. This concerns the provider state directory, not evidence that ordinary long project paths fail.

attempt 1 up · steps

Remaining gaps

  • Tools not immutable. Python 3.13, Postgres 17 and Redis 8 are ranges; uv and jq use latest. Bundle commit and content pins do not freeze tools.
  • Custom service identity. Only Postgres and Redis presets get instance verification; others are liveness-only.
  • Cleanup depends on later activity. Expired leases wait for the next gc or up. Sessions of deleted projects cannot be stopped by Stack.
  • macOS coverage. Native lifecycle smoke passed; the six-suite automation is still Linux-only. x64 was not exercised.
  • Timing rigor. Cold and warm setup are single observations per platform; no randomized repeated study.
  • Scale and real use. No multi-agent task-completion or productivity evaluation, remote or cloud backend, or large concurrency stress.
  • OCI scope. Local anonymous registry only; hosted and private credential-helper workflows untested.

Next recommended improvements

Not yet built or measured. Ordered by how directly each closes a gap in the vision.

  1. Exact tool pins

    Resolve and lock exact provider and tool versions, and remove latest from examples.

    Acceptance A clean cache reproduces identical tool and service versions after upstream releases.

  2. Full macOS CI and an early socket diagnostic

    Run the complete service and session E2E suite on native macOS in CI. Have doctor check the provider socket path length.

    Acceptance Linux contracts repeat on macOS; long state paths are diagnosed before downloads or start.

  3. Extensible identity probes

    Add reusable identity probes for custom services.

    Acceptance A foreign healthy service cannot satisfy an instance check for supported custom bundles.

  4. Deleted-project and automatic cleanup

    Make cleanup independent of project-directory survival and define automatic lease expiry.

    Acceptance Delete a project or lose the runner, and only its owned services are reclaimed without another project starting.

  5. Measured multi-agent pilot

    Run real concurrent agents across projects with controlled failures.

    Acceptance Repeated fresh and cached runs report wrong-instance incidents, orphan rates, task completion and latency distributions.

Reproduce and result data

Usage is documented in each harness docstring. The harnesses run the published package and verify binary hashes; they never build the working tree. Use new result directories to avoid overwriting the recorded runs.

# Fetch the exact published release
npm pack @ushawarma/stack@0.1.3
mkdir -p /tmp/stack-pkg && tar -xzf ushawarma-stack-0.1.3.tgz -C /tmp/stack-pkg
PKG=/tmp/stack-pkg/package

# Linux arm64 benchmark + six E2E suites (needs ev-mise and registry:2 Docker images)
python3 eval/harness/run-stack.py "$PKG" eval/results/repro-linux

# Native macOS arm64 smoke; WORK_DIR must not exist and should be short (socket path cap)
python3 eval/harness/stack-native.py "$PKG" "$(command -v mise)" /tmp/stack-native-repro eval/results/repro-native

# Git tag move with a fresh empty cache
python3 eval/harness/stack-lock.py "$PKG/binaries/darwin-arm64/stack" eval/results/repro-lock
