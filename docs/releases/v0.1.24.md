Stack 0.1.24 replaces Pitchfork with Stack's own per-checkout service supervisor, cuts cold worktree startup and `exec` overhead across concurrent agents, adds multi-checkout fleet traversal, and shrinks the MCP tool schema for coding agents.

### Built-in supervisor & worktree performance
- **Per-checkout supervisor:** each checkout runs its own lightweight supervisor (`stack __supervise`) with zero shared daemon lock, so parallel worktrees start and stop independently without waiting on each other. Log files rotate automatically and drain within a bounded shutdown window before exit.
- **Faster fresh worktrees & `exec` hot path:** new Postgres data directories clone from a local template cluster (copy-on-write on APFS/Btrfs/XFS) instead of running `initdb` every time; Postgres and Redis identity checks query the servers directly over the wire; `mise` environment answers are cached while installed releases remain unchanged; state writes use `fsync` rather than full drive flushes.
- **Safer `stack down`:** `down` tracks running `exec`/`run`/MCP commands per checkout and refuses to confirm stop or purge data while a command is still running. `stack status` now exits `0` when nothing is started.

### Multi-orchestration & agent DX
- **Session labels & fleet commands:** tag sessions with `stack up --label KEY=VALUE` (or MCP `labels`), filter `stack ps` by `--project`, `--state`, or `--label`, and inspect or stop fleets with `stack status`, `stack logs`, and `stack down` using `--project`, `--label`, or `--all` (with non-renewing fleet status and lock-verified fleet down).
- **Lean MCP server & upward discovery:** `tools/list` is ~64% smaller in the default `--profile full` (~25.6 KB, down from ~72 KB) and ~91% smaller in `--profile core` (~6.2 KB, 8 core tools). MCP `dir` arguments now discover `stack.toml` upward from any subdirectory while running `stack_exec` in the requested subdirectory.
- **Safer lease defaults, endpoints & `init --detect`:** `exec --up` and `run --up` default to a 30-minute TTL (configurable via `[session] default_ttl`), `status`/`up` check reports include credential-masked `endpoints`, and `stack init --detect` infers tools and services from existing repo files (`compose.yml`, `package.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`, etc.).

### Reliability & packaging
- Packaged static musl Linux (`x64`/`arm64`) and macOS (`x64`/`arm64`) release binaries are validated against real Postgres, Redis, OCI, and 5-worktree isolation suites in CI.
- Automated GitHub Releases with checksummed `stack-<version>.tgz` tarballs, `SHA256SUMS`, and release notes now publish alongside npm releases.
